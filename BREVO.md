# Налаштування Brevo для SteamSite

SteamSite надсилає лист підтвердження пошти через транзакційний API Brevo.
Нижче — покроково, від реєстрації до перевірки.

## 1. Акаунт Brevo

1. Відкрий [brevo.com](https://www.brevo.com/) → **Sign up free**.
2. Заповни пошту, пароль і назву компанії (можна свою).
3. Підтверди реєстрацію за листом від Brevo.
4. Безкоштовний план: до 300 листів на день — для цього сайту вистачить.

## 2. Відправник (sender) — обов'язково

Brevo відправляє листи тільки з адрес, які ти підтвердив.

1. У лівому меню: **Senders, Domains & Dedicated IPs** → **Senders**.
2. **Add a sender**: ім'я (наприклад `SteamSite`) і пошта, з якої йтимуть листи.
3. На цю пошту прийде лист від Brevo — натисни в ньому **Verify this email**.
4. Статус у списку має стати **Verified**.

Поради:

- Найкраще вказати адресу на **власному домені** (наприклад `no-reply@tvoydomain.com`),
  і додатково автентифікувати домен: **Senders** → **Domains** → **Authenticate**
  (Brevo дасть DKIM/SPF записи для DNS). Це суттєво покращує доставку.
- Адреса `@gmail.com` теж проходить перевірку, але листи частіше потрапляють у спам.

## 3. API-ключ

1. У Brevo справа вгорі — іконка профілю → **SMTP & API**.
2. Вкладка **API Keys** → **Generate a new API key**.
3. Назва, наприклад `SteamSite`, тип ключа — **v3**.
4. Скопіюй ключ одразу: він показується лише один раз (вигляд `xkeysib-...`).

Не вставляй ключ у код, у git або в чат. Він має жити тільки в `.env` локально
і в Environment Variables на Vercel.

## 4. Куди вписати ключ

### Локально

У корені `E:\SteamSite` створи файл `.env` (`.env.example` — це шаблон):

```dotenv
BREVO_API_KEY=xkeysib-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
BREVO_SENDER_EMAIL=no-reply@tvoydomain.com
BREVO_SENDER_NAME=SteamSite
```

Перезапусти `npm start`. Сервер сам читає `.env`.

### На Vercel

1. Проєкт → **Settings** → **Environment Variables**.
2. Додай `BREVO_API_KEY`, `BREVO_SENDER_EMAIL`, за бажанням `BREVO_SENDER_NAME`
   для **Production**, **Preview** і **Development**.
3. **Redeploy** проєкту — без цього змінні не потраплять у функцію.

## 5. Як перевірити

Спочатку можна подивитися, як виглядає лист, без відправки:

```powershell
npm run email:preview
```

Відкриється файл `email-preview/verification.html` — це той самий HTML, який
отримає Brevo.

Потім перевірка реальної відправки на свою пошту:

```powershell
npm run email:test -- tvoya-poshta@example.com
```

Команда покаже `messageId` від Brevo або текст помилки (наприклад, що sender
не підтверджений).

Далі — повний сценарій на сайті:

1. Відкрий сайт → **Зареєструватися** з реальною поштою.
2. Протягом хвилини має прийти лист «Підтверди пошту — SteamSite».
3. Натисни кнопку в листі → відкриється `/verify.html` з повідомленням
   «Пошту підтверджено».
4. Вкладка, де ти реєструвався, сама перекине на каталог уже з входом
   (вона чекає до 5 хвилин).
5. Якщо лист не прийшов — на сторінці входу є кнопка **«Надіслати лист ще раз»**.

## 6. Якщо щось не так

| Симптом | Причина / що робити |
| --- | --- |
| `Brevo відхилив лист (400): sender not valid` | `BREVO_SENDER_EMAIL` не збігається з підтвердженим sender у Brevo |
| `Brevo відхилив лист (401)` | неправильний або відкликаний `BREVO_API_KEY` |
| `Brevo відхилив лист (403)` | у ключа стоїть обмеження за IP — прибери його в налаштуваннях ключа |
| Лист не приходить, помилок немає | перевір папку «Спам», а також що на Vercel був Redeploy після додавання змінних |
| У консолі `[email] Brevo не налаштований…` | не задані `BREVO_API_KEY` і/або `BREVO_SENDER_EMAIL`; лист не надсилається, посилання пише в лог і в `data/outbox/` |
| Посилання у листі веде на `127.0.0.1` | задай `PUBLIC_BASE_URL` з адресою сайту |

## 7. Ліміти

- Безкоштовний план Brevo: 300 листів/день.
- Повторне надсилання листа обмежене 5 спробами на хвилину з однієї IP.
- Посилання підтвердження дійсне 24 години; після підтвердження ним більше
  скористатися не можна.
